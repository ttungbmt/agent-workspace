# Agent Workspace

> A unified workspace for AI-assisted software development.

Agent Workspace is a platform for defining, standardizing, and managing AI development environments across different coding tools and agent runtimes.

It uses a declarative resource model inspired by Kubernetes: you describe the desired state, and Agent Workspace resolves and applies that state to supported runtimes.

## Why

AI coding ecosystems are fragmented.

Each runtime has its own configuration model, extension format, installation flow, permissions, conventions, and lifecycle.

Agent Workspace introduces a shared resource model above those ecosystems so environments can be described consistently, reproduced reliably, and managed centrally.

```text
Declared Resources
       │
       ↓
    Resolve
       │
       ↓
 Desired State
       │
       ↓
 Runtime Adapters
       │
       ↓
 Applied State
```

## Resource Model

Agent Workspace resources follow a Kubernetes-inspired structure:

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Workspace

metadata:
  name: personal-dev

spec:
  profiles:
    - default

  runtimes:
    - claude-code
    - codex
```

Each resource generally contains:

```text
apiVersion
kind
metadata
spec
status
```

### `apiVersion`

Defines the API group and schema version.

Example:

```yaml
apiVersion: workspace.agent/v1alpha1
```

### `kind`

Defines the type of resource.

Example:

```yaml
kind: Workspace
```

### `metadata`

Identifies the resource and contains descriptive information.

Example:

```yaml
metadata:
  name: devops
  labels:
    team: platform
    environment: work
```

### `spec`

Describes the desired state.

Example:

```yaml
spec:
  runtimes:
    - claude-code

  presets:
    - devops
```

### `status`

Represents observed or resolved state.

It is typically generated by Agent Workspace rather than authored manually.

Example:

```yaml
status:
  phase: Ready

  resolved:
    packages: 12
    components: 38

  conditions:
    - type: Resolved
      status: "True"
```

## Core Resources

### Workspace

Represents the top-level desired state of an AI development environment.

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Workspace

metadata:
  name: personal-dev

spec:
  profileRef:
    name: default

  runtimeRefs:
    - name: claude-code
    - name: codex
```

A workspace connects the higher-level resources into one environment.

---

### Source

Defines where packages or components are discovered.

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Source

metadata:
  name: superpowers

spec:
  type: git

  git:
    repository: https://github.com/obra/superpowers
    revision: main
```

Other source types may include:

```text
Git
GitHub
Marketplace
Registry
Local
Internal Repository
```

---

### Package

Represents a distributable unit from a source.

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Package

metadata:
  name: superpowers

spec:
  sourceRef:
    name: superpowers

  version: "4.2.1"
```

A package may provide multiple components.

```text
superpowers
├── brainstorming
├── systematic-debugging
├── test-driven-development
└── verification
```

---

### Component

Represents an individual reusable capability.

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Component

metadata:
  name: systematic-debugging

spec:
  type: Skill

  packageRef:
    name: superpowers
```

Supported component types may include:

```text
Agent
Skill
Command
Hook
MCP
Rule
Workflow
Extension
```

Example:

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Component

metadata:
  name: github

spec:
  type: MCP

  packageRef:
    name: github-integration
```

---

### Preset

Represents a reusable composition of resources.

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Preset

metadata:
  name: devops

spec:
  packages:
    - name: superpowers

  components:
    - name: github
    - name: infrastructure-review

  policies:
    - name: trusted-sources
```

A preset represents a reusable capability stack such as:

```text
frontend
backend
devops
security
research
enterprise
```

---

### Profile

Represents a concrete configuration for a particular working context.

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Profile

metadata:
  name: work

spec:
  presetRefs:
    - name: devops
    - name: security

  runtimeRefs:
    - name: claude-code

  policyRefs:
    - name: strict
```

Another profile may target a different environment:

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Profile

metadata:
  name: personal

spec:
  presetRefs:
    - name: coding

  runtimeRefs:
    - name: claude-code
    - name: codex
```

---

### Policy

Defines governance rules.

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Policy

metadata:
  name: trusted-sources

spec:
  sources:
    allow:
      - anthropics
      - company-internal

  packages:
    requireSignature: true
```

Policies may govern:

```text
Sources
Packages
Permissions
Capabilities
Runtime access
Versions
Security requirements
Trust
```

---

### Runtime

Describes a supported AI coding runtime.

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Runtime

metadata:
  name: claude-code

spec:
  adapter: claude-code

  scope: project
```

Example runtimes:

```text
Claude Code
Codex
Gemini CLI
Cursor
OpenCode
GitHub Copilot
```

---

### Adapter

Defines how Agent Workspace resources are translated into runtime-native configuration.

```yaml
apiVersion: workspace.agent/v1alpha1
kind: Adapter

metadata:
  name: claude-code

spec:
  runtime: claude-code
```

Conceptually:

```text
Agent Workspace Resources
          │
          ↓
       Adapter
          │
          ↓
Runtime-native Configuration
```

For example:

```text
Claude Code Adapter
├── .claude/
├── CLAUDE.md
├── settings.json
└── .mcp.json
```

---

## Resolution

Resources reference each other rather than embedding everything into one large configuration file.

For example:

```text
Workspace
   │
   ↓
Profile
   │
   ├── Preset
   │      ├── Package
   │      │      └── Component
   │      └── Policy
   │
   └── Runtime
          │
          ↓
        Adapter
```

The resolver builds the final desired state.

```text
Resources
   ↓
Reference Resolution
   ↓
Dependency Resolution
   ↓
Conflict Resolution
   ↓
Policy Evaluation
   ↓
Resolved State
```

## Lock State

A resolved environment may be captured in a lock resource or generated lockfile.

```yaml
apiVersion: workspace.agent/v1alpha1
kind: WorkspaceLock

metadata:
  name: personal-dev

spec:
  packages:
    - name: superpowers
      version: "4.2.1"
      revision: abc123

    - name: internal-devops
      version: "1.3.0"
      revision: def456
```

This makes the environment reproducible across machines and projects.

## Reconciliation

Agent Workspace follows a desired-state model.

```text
          Desired State
               │
               ↓
            Resolver
               │
               ↓
           Reconciler
          ↙         ↘
Current State     Desired State
          \         /
           \       /
             Diff
               │
               ↓
              Apply
```

The system continuously compares:

```text
what is declared
```

with:

```text
what is actually installed and configured
```

and determines the actions required to converge them.

```text
Resource Manifests
       │
       ↓

       │
       ├── Validate
       ├── Resolve
       ├── Evaluate Policies
       ├── Reconcile
       └── Lock
              │
              ↓
       Runtime Adapters
       ┌──────┴──────┐
       ↓             ↓
 Claude Code       Codex
```

## Philosophy

Agent Workspace is not another collection of AI coding plugins.

It is a declarative control layer for AI development environments.

The project follows a few core principles:

- Declarative desired state
- Resource-oriented configuration
- One API model across multiple runtimes
- Explicit references between resources
- Reproducible resolution
- Composable resources
- Runtime-independent architecture
- Policy-aware management
- Observable state
- Reconciliation instead of one-time installation

## Vision

AI development environments should be manageable like modern infrastructure.

You should be able to declare the desired environment once, version it, review it, reproduce it, and apply it consistently across projects, machines, teams, and AI coding runtimes.

Agent Workspace aims to become the control plane for that environment.

## Status

Early development.

The API model, resource schemas, resolver, reconciler, runtime adapters, and management interfaces are currently being designed and validated against existing AI coding ecosystems.
